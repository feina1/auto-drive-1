## 一、整体架构

```
每 1 秒:
  取过去 5 帧图片 [5 × 640×360×3]
      ↓
  DINOv3 (frozen) 逐张提特征
      ↓
  时序聚合: 5 帧特征取平均 → [384]
      ↓
  Waypoint Head (MLP) → [10, 2] (前方 0~9m, 每隔 1m 一个点)
      ↓
  局部参考路径 (10 个 ego waypoints)
      ↓
  PID 按这 10 个点跟踪行驶 (10Hz)
      ↓
  下一秒，再次推理，更新局部参考路径
```

## 二、模型设计

### 输入
- 5 张 RGB 图片 (640×360)，时间跨度 1 秒 (5Hz × 5帧)
- 纯视觉，不含任何定位/GPS/IMU 信息

### DINOv3 特征提取 (frozen)
- 每张图 → DINOv3 → CLS token [384] + mean(patches) [384]
- 5 帧的特征取平均: `feat = mean([feat_t, feat_t-1, ..., feat_t-4])` → [384]
- 简单平均即可，DINOv3 的 CLS token 已经有很强的语义信息

### Waypoint Head
```
输入: [384] (5帧平均特征)
  → Linear(384 → 256) → GELU → Dropout(0.1)
  → Linear(256 → 256) → GELU → Dropout(0.1)
  → Linear(256 → 20)  → reshape → [10, 2]
输出: 10 个 waypoints (ego frame, 单位: 米)
```

### 输出格式
- 10 个点，分别代表前方 0m, 1m, 2m, ..., 9m 的位置
- 坐标系: ego frame (x=前方, y=左方)
- 第 0 个点理论上接近 (0, 0)（车辆当前位置）
- 第 9 个点是前方 9m 处的目标位置

### 可训练参数
- DINOv3: 21.6M (frozen, 不训练)
- Waypoint Head: ~167K (只训练这部分)

## 三、GT 标签生成

### 生成逻辑 (V0 中心线 Oracle)
对每一帧:
1. 在**全局参考路径**上找到车辆最近点 (投影)
2. 从该点开始，沿参考路径向前，每隔 1m 采样一个点
3. 采 10 个点: 0m, 1m, 2m, ..., 9m
4. 将这些点从世界坐标系转换到 ego 坐标系 (x=前方, y=左方)

### 关键点
- GT 标签**始终基于全局参考路径**，不管车辆实际在哪
- 即使车辆偏到了对向车道，GT 标签仍然指向正确车道
- 这就是模型要学的东西: "看到这张图，我知道要往哪走才能回到正确车道"

### 标签质量过滤
- 跳过 offroad 帧 (车辆完全出了赛道边界)
- 跳过 collision 帧 (碰撞后物理不可信)
- 横向误差 > 5m 的帧也跳过 (已经无法恢复了)

## 四、数据准备方案

### 目标
让模型学会:
1. 弯道怎么转
2. 偏右了怎么回来
3. 偏左了（甚至到对向车道）怎么回来
4. 正常直行时保持稳定

### 录制策略
使用扰动注入录制，但要更有针对性:

**扰动类型和强度:**

| 类型 | 横向偏移 | 航向偏移 | 占比 | 训练目标 |
|------|---------|---------|------|---------|
| 小扰动 | ±0.2~0.5m | ±2~5° | 30% | 正常行驶微调 |
| 中扰动 | ±0.5~1.2m | ±5~10° | 30% | 明显偏移纠偏 |
| 大扰动 | ±1.2~2.5m | ±10~20° | 25% | 大幅偏移恢复 |
| 超大扰动 | ±2.5~4.0m | ±15~30° | 15% | 极端情况（到对向车道） |

**扰动频率:**
- 每 2~4 秒施加一次扰动（比之前更频繁）
- 扰动后等待 2~3 秒 cooldown（让 PID 纠偏，这些帧就是纠偏样本）

**录制圈数:**
- 至少 10 圈（约 260km 行驶距离）
- 覆盖足够多的弯道和直行场景

**数据量估算:**
- 10 圈 × ~3300 帧/圈 = ~33000 帧
- 跳过 offroad/collision 后约 ~28000 有效帧
- 每 5 帧一组 (temporal sequence): ~5600 组训练样本

### 与之前数据的区别
- 之前: 3307 帧扰动 + 16690 帧原始 = 20000 帧，但 GT 是 5m 间隔 6 个点
- 现在: 需要重新录制，GT 改为 1m 间隔 10 个点
- 之前的数据**不能直接复用**（GT 格式不同，且输入从单帧改为 5 帧）

## 五、训练配置

### 数据组织
每个训练样本:
```python
{
    "images": [img_t-4, img_t-3, img_t-2, img_t-1, img_t],  # 5 张图
    "gt_waypoints": [[0,0], [1,0], [2,0], ..., [9,0]],       # 10 个点, ego frame
}
```

### 超参数
- Batch size: 32 (5 张图占显存，不能太大)
- Epochs: 500
- Optimizer: AdamW, lr=3e-4, weight_decay=1e-4
- Scheduler: CosineAnnealing
- Loss: 加权 L2
  - 权重: [1.0, 2.0, 2.5, 2.5, 2.0, 1.5, 1.2, 1.0, 0.8, 0.6]
  - 近处权重高（0~2m 最关键），远处权重低

### 特征增强
- Gaussian noise (σ=0.02)
- Random dropout (p=0.05)
- 时序 dropout: 随机丢弃 1~2 帧（模拟丢帧）

## 六、Run 脚本设计 (train/run.py)

### 运行流程
```python
while not done:
    # 每帧 (10Hz):
    #   1. 捕获当前图片 → 存入帧缓冲区
    #   2. 如果有最新的模型输出 (10 waypoints):
    #      PID 按这 10 个 waypoints 计算控制量
    #   3. env.step(control)
    
    # 每 1 秒 (1Hz):
    #   4. 从缓冲区取最近 5 帧
    #   5. 模型推理 → 输出 10 个局部 waypoints
    #   6. 更新 PID 的目标路径
```

### PID 跟踪局部路径
- 复用现有的 Pure Pursuit + PID 逻辑
- 输入从全局参考路径改为模型输出的 10 个局部 waypoints
- 如果当前速度下 10m 不够看（70km/h ≈ 19.4m/s），可以适当外推

### 监控指标
- 实时横向误差（与全局参考路径比较）
- 速度
- 转向角
- 圈数

## 七、实施步骤

1. **重新录制数据**
   - 改进扰动注入脚本（更大的扰动范围）
   - 录制 10 圈

2. **GT 标签生成**
   - 1m 间隔 × 10 个点
   - ego frame 坐标系
   - 5 帧 temporal sequence 组织

3. **模型构建**
   - 5 帧 DINOv3 特征提取 + 时序聚合
   - Waypoint Head 输出 10 个点

4. **训练**

5. **闭环测试 (run.py)**
   - 1Hz 推理 + 10Hz PID 跟踪
   - 目标: 1 圈，偏移 < 2m

## 八、风险与应对

| 风险 | 应对 |
|------|------|
| 10m 局部路径在高速下不够看 | PID 可以做线性外推，或增大到 15~20m |
| 5 帧时序输入增加显存占用 | 降低 batch size 到 16 |
| 大偏移样本 PID 无法恢复 | 录制时设置最大偏移阈值，超过就重置 |
| 模型输出的路径不平滑 | 加平滑约束或后处理 |
