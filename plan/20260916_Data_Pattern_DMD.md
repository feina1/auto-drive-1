# Data Pattern (DMD) — 端到端训练的数据怎么录

日期: 2026-09-16

## 摘要

浩哥反馈：量产自动驾驶的数据录制不会刻意把数据打散。当前方案（PID + 固定参考路径 + 人为扰动）存在根本问题——训练数据和模型实际遇到的场景不一致（分布偏移）。

核心结论：不要人为扰动，要让场景和驾驶行为本身多样化。具体做法是两点：(1) 用多种驾驶风格（不同速度、不同 PID 参数）在现有赛道上收集数据；(2) 用 DAgger 闭环迭代，让模型自己犯的错误成为训练数据。多赛道场景本次不做，因为赛道搭建已经花了不少时间，留给后续迭代。

## 当前方案的问题

行为克隆的固有缺陷——分布偏移：

训练时专家完美驾驶，模型只见过"车在路中间"的画面。推理时模型产生小误差，车辆偏离，画面变得陌生，模型做出更大误差，最终崩溃。

之前尝试的"人为注入扰动"（横向偏移 ±5m、航向 ±30°）本质上是在制造一个不自然的数据分布。向领导汇报时也难以解释——为什么要人为给数据增加难度？

## 量产自动驾驶怎么做的

量产数据不靠人为打散，靠的是：覆盖足够多的真实场景（不同的路、不同的交通状况），包含足够多的驾驶风格（激进、保守、正常），以及用模型自身的错误来迭代改进。

数据多样性来自场景本身，不是来自人为扰动。

## 本次要做的事

### 1. 多驾驶风格数据收集

在现有赛道上，通过改变驾驶参数来产生数据多样性：

- 不同速度：50 / 60 / 70 / 80 km/h
- 不同 PID 参数：P 值大 = 激进（贴近车道线、快速修正），P 值小 = 保守（居中行驶、缓慢修正）
- 每种组合都是"合理的驾驶方式"，不是人为扰动

合在一起，数据自然覆盖了从小偏离到大偏离的全部范围。

### 2. DAgger 闭环迭代

DAgger 属于模仿学习（不是强化学习），是行为克隆的升级版。核心思路：

第一轮：用专家数据训练初始模型。第二轮：让模型自己开，遇到它处理不了的情况时 PID 专家接管纠正，记录全过程。第三轮：用累积数据重新训练。重复迭代。

关键点：模型自己犯的错误成为训练数据的一部分，不需要人为扰动。每一轮迭代，模型能处理的场景越来越多。

### 3. 多赛道场景（本次不做）

用 MetaDrive 程序化生成多种赛道（直道、弯道、S弯、环岛等）来增加场景多样性。这个方向是对的，但赛道搭建已经花了大量时间，本次不做，后续迭代时再考虑。

## 向领导汇报时的说法

"我们用 MetaDrive 仿真环境，通过多种驾驶风格和 DAgger 闭环迭代来收集训练数据。模型在仿真中自动驾驶，遇到处理不了的情况由专家接管，累积数据后重新训练，迭代改进。"

这比"人为注入扰动"合理得多——数据多样性来自场景覆盖和模型自身迭代，不是人为制造困难。
