# 训练设计

## 一、任务定义

模型从纯视觉输入预测局部参考路径。

输入: 5 帧 RGB 图片 (5Hz, 1 秒内)
输出: 10 个 waypoints (ego frame, 1m 间隔, 前方 0~9m)
推理频率: 1Hz (每秒一次)

模型要学会: 看到图片就知道应该走什么路径。在弯道上要输出正确的弯道路径, 偏移了要输出回到正确车道的路径。

## 二、模型架构

```
5 帧图片 [5, 3, 224, 224]
    ↓ (每张独立过 DINOv3)
DINOv3 (frozen, 21.6M params)
    ↓
5 个特征向量 [5, 384]
    ↓ (取平均)
时序聚合特征 [384]
    ↓
Waypoint Head (MLP, ~167K params)
    Linear(384 → 256) → GELU → Dropout(0.1)
    Linear(256 → 256) → GELU → Dropout(0.1)
    Linear(256 → 20) → reshape → [10, 2]
    ↓
10 个 waypoints (ego frame, 米)
```

### 为什么 5 帧取平均而不是拼接

- 拼接 [5×384=1920] 参数量太大, 容易过拟合
- 取平均保留了"这 1 秒内的整体视觉语义", DINOv3 的 CLS token 已经编码了足够的场景信息
- 如果后续发现平均不够用, 可以换成 attention pooling 或 GRU

### 为什么输出 10 个点

- 10m 前方路径在 70km/h 下约 0.5 秒的行驶距离
- 模型每 1 秒推理一次, 两次推理之间有重叠
- 1m 间隔足够密, PID 跟踪平滑
- 如果 10m 不够 (高速场景), 可以外推或增大到 15~20m

### 数据加载

## 四、损失函数

加权 L2 loss:

```python
# 预测和真值
pred = model(frames)          # → [batch, 10, 2]
gt = batch["gt_waypoints"]    # → [batch, 10, 2]

# 逐点 L2 距离
per_point_loss = F.mse_loss(pred, gt, reduction='none').mean(dim=-1)  # → [batch, 10]

# 权重: 近处重要, 远处次要
weights = torch.tensor([2.0, 2.5, 2.5, 2.0, 1.5, 1.2, 1.0, 0.8, 0.6, 0.5])

# 加权平均
loss = (per_point_loss * weights).mean()
```

权重设计理由:
- 0~2m (权重 2.0~2.5): 最关键, 决定立即转向
- 3~5m (权重 1.5~2.0): 中距离, 决定弯道趋势
- 6~9m (权重 0.5~1.0): 远距离, 提供方向参考

## 五、训练超参数

| 参数 | 值 | 理由 |
|------|-----|------|
| Batch size | 32 | 5 帧占显存, 不能太大 |
| Epochs | 500 | 1000 段数据不多, 需要多轮 |
| Optimizer | AdamW | 标准选择 |
| Learning rate | 3e-4 | 只训练 head, 可以稍大 |
| Weight decay | 1e-4 | 防过拟合 |
| Scheduler | CosineAnnealing | 平滑衰减 |
| Train/Val | 80%/20% | 800 训练, 200 验证 |
| Early stopping | 50 epochs | val loss 不降就停 |

## 六、特征增强

训练时对 DINOv3 提取的特征做增强, 防过拟合:

1. **Gaussian noise**: σ=0.02, 模拟特征噪声
2. **Feature dropout**: p=0.05, 随机屏蔽部分特征维度
3. **Temporal dropout**: 随机丢弃 1~2 帧 (5 帧变 3~4 帧), 模拟丢帧
4. **Image augmentation**: 对输入图片做轻微增强
   - Random horizontal flip (翻转时 GT waypoints 的 y 也翻转)
   - Color jitter (亮度/对比度 ±10%)

## 七、评估指标

### 离线评估 (验证集)

1. **Mean L2**: 预测 waypoints 和 GT 的平均欧氏距离 (m)
2. **Max L2**: 最大单点误差 (m)
3. **Direction error**: 预测路径方向与 GT 方向的平均角度差 (°)
4. **Endpoint error**: 最后一个点 (9m 处) 的误差

### 在线评估 (闭环测试)

1. **完成圈数**: 能否完成 1 圈
2. **Mean lateral error**: 与全局参考路径的平均横向偏差 (m)
3. **Max lateral error**: 最大横向偏差 (m)
4. **90%ile lateral error**: 90% 分位的横向偏差
5. **Off-road frames**: 出界的帧数占比

### Baseline 目标

- 完成 1 圈
- Mean lateral error < 2m
- 90%ile lateral error < 3m

## 八、训练流程

```
1. 加载 1000 段数据
2. 对每段:
   a. 5 帧图片 → DINOv3 → 5 个特征 → 取平均 → [384]
   b. 缓存特征 (训练时不再过 DINOv3)
3. 划分 train/val (800/200)
4. 训练循环:
   for epoch in range(500):
       # Train
       for batch in train_loader:
           pred = head(batch.features)  # → [32, 10, 2]
           loss = weighted_l2(pred, batch.gt_waypoints)
           loss.backward()
           optimizer.step()
       
       # Validate
       val_loss = evaluate(head, val_loader)
       if val_loss < best_val_loss:
           save_checkpoint(head)
       
       # Log
       print(f"Epoch {epoch}: train_l2={train_loss:.3f} val_l2={val_loss:.3f}")
5. 保存最佳 checkpoint
```

## 九、迭代策略

### 第一轮 (baseline)
- 1000 段数据
- 简单 MLP head
- 目标: val_l2 < 0.5m, 闭环 Mean L2 < 2m

### 如果 baseline 不达标
1. 增加数据量 (2000~3000 段)
2. 增大扰动范围 (更多极端场景)
3. 换更强的 head (attention pooling, Transformer decoder)
4. 增加数据增强

### 如果 baseline 达标
1. 尝试更快速度 (80, 90 km/h)
2. 尝试更复杂的赛道
3. 增加时序建模 (GRU/Transformer 替代简单平均)
4. 端到端训练 (解冻 DINOv3 最后几层)

## 十、Run 脚本设计 (train/run.py)

```
while not done:
    # 每帧 (MetaDrive 仿真步进):
    #   1. 捕获当前图片 → 存入帧缓冲区
    #   2. 如果有最新 waypoints:
    #      PID 按这 10 个 waypoints 计算控制
    #   3. env.step(control)
    
    # 每 1 秒 (1Hz):
    #   4. 从缓冲区取最近 5 帧
    #   5. 模型推理 → 10 个局部 waypoints
    #   6. PID 更新目标路径
    #   7. 记录: 横向误差、速度、转向
```

PID 跟踪局部路径:
- 复用 Pure Pursuit + PID 逻辑
- 输入从全局参考路径改为模型输出的 10 个局部 waypoints
- 如果速度高 (70km/h), 10m 可能不够看
  - 方案 A: 对最后几个点做线性外推到 15~20m
  - 方案 B: 提高推理频率到 2Hz
